# PR 自動レビュー

PR の差分を3つのサブエージェントに別々に見せ、結果を1件のまとめコメントとして PR に投稿する。コードは修正しない。

## 0. 対象の PR を決める

1. 同じセッションで作成・更新した PR があれば、その番号を使う。
2. なければ、現在のブランチ名で `mcp__github__list_pull_requests` を使い、Open の PR を探す。
3. PR が見つからない、または Open でない場合は、投稿せずに中止し、その理由を画面に書く。

確定させる値: リポジトリ（owner/repo）、PR 番号、base ブランチ、現在の HEAD の完全な SHA（`git rev-parse HEAD`）。

## 1. 前回レビューの確認

1. PR のコメント一覧を取得する。
2. 本文に `<!-- pr-review-last-sha:` を含む、最新のまとめコメントを探す。
   - 見つからない → **初回レビュー**。
   - 見つかった → **差分レビュー**。コメントに書かれた SHA を起点にする。
3. 差分レビューの場合は、起点の SHA が今の履歴にあるか確かめる。
   - `git cat-file -e <SHA>` が失敗する、または `git merge-base --is-ancestor <SHA> HEAD` が偽 → 強制プッシュなどで起点が消えたとみなす。PR 全体をレビューし直し、コメントに「前回のコミットが見つからなかったため、PR 全体を再レビューした」と明記する。
4. 前回のまとめの「指摘一覧」を読む。各指摘について、今回の差分で直っているかを確かめる。直っているものは「対応済み」として扱い、変更のない箇所は再び指摘しない。

## 2. 差分とコードを読む

- 差分は git で取る。起点のコミットがローカルになければ `git fetch origin <ブランチ名>` を実行する。
  - 初回: `git diff origin/<base>...HEAD`
  - 差分: `git diff <前回のSHA>..HEAD`
- 差分と変更ファイル一覧を、作業用の一時ファイル（作業ディレクトリの外）に保存する。サブエージェントにはそのパスを渡す。
- 変更されたファイルは、差分の周辺も読む（変更箇所を含む関数やモジュール全体、その呼び出し元）。差分だけで判断しない。

## 3. 3つのサブエージェントを並列に起動する

Agent ツールを3回、**1つのメッセージで同時に**呼ぶ。サブエージェントどうしは結果を見られない。

| subagent_type | 視点 |
| --- | --- |
| `pr-review-bugs` | A. バグ・脆弱性（厳しめ） |
| `pr-review-readability` | B. 第三者視点（読みやすさ・説明） |
| `pr-review-cost` | C. 実用性・コスト |

各サブエージェントに渡す内容（プロンプト）:

- レビューの種類（初回／差分）、PR 番号、base と HEAD、差分ファイルのパス、変更ファイル一覧
- 前回の指摘一覧（あれば）。重複を避けるため、同じ箇所の指摘は再度書かないよう指示する
- 「差分とコードだけで判断する。PR の説明や、この会話の内容は参照しない」
- 出力形式は各サブエージェントの定義に従うことを伝える

## 4. まとめる

1. 3つの結果を統合し、同じ箇所の重複をまとめる。
2. 重大度を付ける: **高／中／低**。
3. 視点によって意見が分かれた点は、両方の意見を残し、「視点によって意見が分かれる」と注記する。
4. 確証がない指摘には「要確認」と明記する。
5. 前回の指摘のうち、対応済みのものを一覧にする。

## 5. PR に投稿する

- `mcp__github__add_issue_comment` で、対象の PR に**まとめのコメントを1件**投稿する。新しい PR やブランチは作らない。
- 本文の形式は次のとおり。

```
## 自動レビュー（初回 ／ 追加コミットの差分）

- 対象コミット: <base>...<HEAD（初回）> または <前回のSHA>..<HEAD（差分）>（<件数> 件）
- 総評: （3行程度）

### 重大度: 高
- [確度: 確実／要確認] `ファイル:行` — 内容。根拠。修正の方向性（コードは書かない）

### 重大度: 中
（同じ形式）

### 重大度: 低
（同じ形式）

### 視点で意見が分かれた点
（あれば。なければ「なし」）

### 前回の指摘への対応状況
（差分レビューのみ。「対応済み」「未対応」を一覧にする。初回は省く）

### 指摘一覧（次回の照合用）
- ID・ファイル・要約・状態（未対応／対応済み）を1行ずつ

<!-- pr-review-last-sha: <HEAD の完全な SHA> -->

---
_Generated by [Claude Code](https://claude.ai/code)_
```

- 本文に、トークン・パスワード・APIキーの値そのものや、締切などの個人情報を書かない。場所だけを書く。
- 指摘がない場合も、まとめのコメントは投稿する（「指摘なし」と書き、マーカーは必ず入れる）。

## 6. 画面への表示

投稿後、画面には次の2行だけを短く表示する。

- 重大度「高」の件数
- まとめのコメントの URL

## 禁止事項

- 指摘を自分でコードに反映しない。コードの修正は利用者が指示したときだけ行う。
- 新しい PR やブランチを作らない。
- サブエージェントの結果を、この会話の内容と混ぜて判断しない（各サブエージェントの判断を尊重する）。
