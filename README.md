# 部内大会トーナメント

部内大会のトーナメント表・総当たり表を作り、結果入力・順位集計・掲示物の出力までを行うアプリです。
ブラウザ版（GitHub Pages）と Windows 版（`.exe`）があり、どちらも同じ画面・同じ機能です。

## できること

- 参加者名簿からトーナメント表（2〜128人）・総当たり表（2〜40人）を自動作成
- 参加者名・卓名の編集（作成後の名前変更も表に反映）
- 初めて使うとき: 参加者が0人の「参加者・設定」に案内が出て、名前の追加・一括入力に進める。表が無いタブにも、次にすることが出る
- 閲覧者からの結果報告: 共有の閲覧者が、終わった試合の結果を運営に報告できます。運営が承認すると表に反映されます（承認するまでは表に出ません）
- スマホでの総当たり: 画面の幅が狭いときは、回戦ごとのタブで試合を見られます（奇数人数のときは休みの人も出ます）。「対戦表で見る」では、選手を選ぶと、その人の対戦だけが縦に並びます
- 閲覧リンクのQRコード: 共有の画面の「QRコード」で、閲覧リンクを大きく表示（全画面・PNG保存つき）。会場の掲示・スクリーンで、スマホで読み取るだけで開ける
- 元に戻す: ヘッダーの「元に戻す」・Ctrl+Z で、直前の操作を取り消せる（最大20回前まで。ページを再読み込みすると消える）。スマホのメニューでは、何が戻るか（「直前：結果の保存（No.3）」など）が名前の下に出る
- 作成前の組み合わせ確認: 「トーナメント表を作成」で1回戦の組み合わせを確認し、2人を続けて押して入れ替え、抽選をやり直せる
- キーボード操作（総当たり）: 対戦表は Tab で入り、矢印キーでマスを移り（Home／End で行の先頭・最後）、Enter か Space で結果入力。試合結果一覧の表の行も、上下の矢印キーで移れる
- 当日の出欠確認: 名簿の「出席」チェックで欠席を記録し、表の作成時に欠席の人を除くか不戦にするかを選べる。表に入れたままの欠席の人には、トーナメント表・総当たり表・試合結果一覧・順位表（共有の閲覧画面も）で名前の後ろに「欠席」の印が付く（CSV・PNG は「（欠席）」の文字）
- 使用する卓の数、シード（なし／ランダム／名簿でチェックして指名）、シード以外の配置（名簿順／抽選）、3位決定戦の有無を指定
- 試合結果（スコア・勝者・不戦勝）を入力すると、勝者が次の回戦へ自動で進む
- 結果を修正すると、矛盾する後続の試合結果を確認のうえ取り消す
- 表の下に試合結果一覧（試合番号・卓・時間帯・スコア・勝者・状態）
- 順位表（トーナメント: 敗退回戦順／総当たり: 勝点→直接対決→得失点差→総得点）
- トーナメント表・総当たり表・試合結果・順位表を CSV / PNG で出力、印刷
- 大会データの自動保存、ファイルへの保存・読込、名簿の CSV 取込（UTF-8 / Shift_JIS）
- 共有の閲覧者は、名前を選ぶと「あなたの次の試合」（卓・対戦相手・試合番号）が出て、表の中の自分の名前が強調されます（運営の画面にも同じ機能があり、最初はオフです）
- 端末の設定がダークモードのときは、画面もダークになります（印刷と PNG 出力は白背景のままです）
- 進行状況（終了数、次に行う試合と卓）。結果入力の「保存して次へ」（Ctrl+Enter）で、続けて次の試合を入力
- 呼び出し画面: 進行中の試合と次に行う試合を、卓名・対戦者つきで大きく表示（プロジェクター・大型ディスプレイ向け）
- 試合の開始: 進行状況の卓ごとのカードの「開始」で進行中にし、経過時間と卓ごとの空き状況・次の試合を表示（取り消しは、その試合の結果入力の画面から）
- 大会の回数（第2回大会など）: 同じ参加者・卓・設定のまま次の大会を始め、前の大会は「過去の大会」として残して見返せる
- 共有（任意）: 大会データを公開し、閲覧者がスマホ等で見る・コメントする（共有コード＋パスワード）

## 使い方

1. 「参加者・設定」で参加者を入力（タブの上の「1 大会情報と参加者 → 2 卓と形式 → 3 表を作成」の順に進めます。押すとその位置へ移動します。1人ずつ追加、または「一括入力・CSV取込」）
2. 卓の数・卓名、シードの決め方（ランダム、または名簿の名前の左のチェックで指名）などを設定し、「トーナメント表を作成」「総当たり表を作成」（トーナメントは、作る前に1回戦の組み合わせが出ます。選手を2人続けて押すと入れ替わり、ランダムのときは「抽選をやり直す」もできます。「この組み合わせで作成」で確定します）
3. 「トーナメント」「総当たり」タブで試合（表のマス・試合・一覧の行・「次に行う試合」）をクリックし結果を入力（総当たりの「試合結果一覧」は、状態・回戦・卓・選手名で絞り込めます。CSV・PNG・印刷は常に全試合です）
4. 「順位表」で結果を確認。各表の上の「出力」ボタンから、CSV / 画像（PNG）で保存、または「印刷」（A4横）
5. 当日来ない人がいるときは、名簿の「出席」のチェックを外します。表を作るときに「欠席の人を除いて作る」か「欠席の人を入れたまま、その試合を不戦にする」かを選べます。表を作ったあとに欠席にしたときは、その人の試合を不戦（相手の不戦勝）にするかを聞きます。次の大会は全員出席から始まります。
6. 開催日時は「参加者・設定」の「大会情報」で入力します（過去の日付・時刻は設定できません。時刻は空欄でも構いません）。
7. データはブラウザ（Windows 版はPC）に自動保存されます。別のPCへ移す・控えを残すときはヘッダーの「保存」で JSON ファイルに書き出し、「読込」で開きます

## 第2回大会など（大会の回数）

同じメンバーでもう一度大会を行うときは、表を作り直さずに「次の大会」を始めます。

1. 「参加者・設定」タブの一番下の「大会の回数」のカード（過去の大会がないときは折りたたまれているので、見出しを押して開く）、または、トーナメント・総当たりが終わったときに出る「第2回大会を始める」を押す
2. 参加者・卓・設定はそのまま引き継がれ、表と結果が新しくなります（開催日時は入れ直してください）。今の大会は「過去の大会」に残ります
3. 名簿を調整して、トーナメント表・総当たり表を作成し、これまでと同じように進めます
4. 過去の大会は、「大会の回数」のカードの一覧の「見る」で、読み取り専用で見られます（表・結果一覧・順位表、CSV/PNG 出力、印刷）。画面上部のバナーで他の大会へ切り替えたり、今の大会へ戻ったりできます。不要な大会は「削除」できます
5. 総当たり（予選リーグ）のあとに決勝トーナメントを行うときは、「順位表」タブの総当たりの順位表の下にある「この人たちで第N回大会を始める」を使います。上位N人だけが順位順の名簿になって次の大会が始まるので、そのままトーナメント表を作成できます（境目に同順位の選手がいるときは確認の画面で知らせます。始めたあとに名簿で入れ替えられます）
6. 大会名には、過去の大会があるときだけ「第N回」が付きます（画面・印刷・出力ファイル名）。過去の大会は保存ファイル（JSON）にも入ります。20回までです

共有を使っているときに次の大会を始めると、閲覧者の画面も新しい大会の内容（表ができるまでは「まだ作成されていません」）に変わります。閲覧者は「次の大会を始める」はできませんが、画面上部の「過去の大会の結果も見られます」から、公開された過去の大会を読み取り専用で見られます（見ている間に運営が進めても画面は変わらず、「今の大会に戻る」で最新が出ます）。共有に送るデータが大きいときは、古い大会から順に共有へ載せなくなります（この端末のデータは変わりません）。

## 呼び出し画面（会場向けの大きな表示）

「トーナメント」「総当たり」タブの進行状況の欄にある「呼び出し画面」を押すと、次に行う試合が、卓名・対戦者つきで大きく表示されます。「全画面」でプロジェクターや大型ディスプレイに映せます（Esc で閉じる）。結果を入力すると自動で更新されます。進行状況の欄には、卓ごとに1枚のカードが並び、「今」（進行中の試合か「空き」）と「次」（その卓の次の試合）が出ます（共有の閲覧者にも見えます）。空きの卓の「開始」を押すと、その卓の次の試合が「進行中」になり、経過時間（分）が出ます。進行中の卓は「結果を入力」で結果を入れます。開始を間違えたときは、その試合の結果入力の画面の「開始を取り消す」で戻せます。

PC 1台にプロジェクターをつないで、呼び出し画面を映しながら手元で入力したいときは、呼び出し画面の「別ウィンドウで開く」を押してください。呼び出し画面だけの別のウィンドウが開き（元の画面の呼び出し画面は閉じます）、そのウィンドウをプロジェクター側へ動かして「全画面」にします。運営の画面で結果を入れると、別のウィンドウもすぐに更新されます（同じパソコンの中の通知で、共有サーバーは使いません）。別のウィンドウは読み取り専用で、運営の画面を閉じても最後の内容を出し続けます。Windows 版（`.exe`）でも使えます。

`file://` でファイルを直接ブラウザで開いているときは、ブラウザによっては、別のウィンドウに更新が届かないことがあります（同じ場所のデータの扱いがブラウザごとに違うため）。更新されないときは、Windows 版か、`https://` で公開したページ（GitHub Pages）で使ってください。

運営が入力する端末とは別の端末で映したいときは、共有（下記）の閲覧リンクを別の端末で開いて「呼び出し画面」を押してください（運営の入力が約15秒以内に反映されます）。

## Web 版（GitHub Pages）

`main` ブランチに push すると `.github/workflows/pages.yml` がビルドして公開します。

初回のみリポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にしてください。
公開URL: `https://<ユーザー名>.github.io/<リポジトリ名>/`（このリポジトリなら `https://bibi257.github.io/-/`）

ビルド後の `web/` フォルダは静的ファイルだけなので、`web/index.html` をダブルクリックしてもオフラインで動きます。

## 共有機能（閲覧者への公開・コメント）

運営が入力した大会データを、パスワード付きで閲覧者に見せられます。閲覧者は結果を変更できず、コメントだけ書けます。
GitHub Pages は静的ファイルしか置けないため、データの置き場として**共有サーバー**（Cloudflare Workers + D1、無料枠で足ります）を別に使います。
共有サーバーはアプリの画面も配信するので、そのURL1つで「運営」も「閲覧」も使えます。共有を使わない場合は何も設定しなくて構いません。

### 使い方
- 運営: ヘッダーの「共有」→ 共有サーバーのURLと運営用パスワード（自分専用・確認のため2回入力）を入力して「共有を始める」。
  表示される閲覧リンクを参加者に伝えます。以後、結果入力などの変更は自動で送信されます。閲覧リンクの横の「QRコード」を押すと、リンクのQRコードを大きく表示します（「全画面」でスクリーンに映す、「画像（PNG）で保存」で掲示物に貼る）。参加者はスマホのカメラで読み取るだけで開けます
- 閲覧: 閲覧リンクを開くだけです（パスワードは不要）。表・結果・順位表を見られ、「コメント」タブで書き込めます（15秒ごとに自動更新）。この端末に自分の大会データがあるときは、確認してから入ります
- 閲覧者は「コメント」タブの「試合結果を報告」から、終わった試合の結果（勝者・スコア）を運営に報告できます。運営の「コメント」タブの「結果の報告」に承認待ちが並び（タブに「報告N」と出ます）、「承認して表に反映」で表に入ります。「却下」で取り消せます。運営が先に入力した試合の報告は承認できません
- 運営はコメントを削除でき、運営用パスワードの変更、共有の終了（サーバー上のデータを削除）もできます
- 運営が入力できるのは1人だけです（複数端末から同時に入力すると、最後に送った内容が残ります）
- GitHub Pages の画面から使うときは、共有サーバーのURLを入力します。サーバーのURLの画面（`https://tournament.○○.workers.dev/`）から開けば入力不要です

### 共有サーバーの用意（初回のみ）
Cloudflare の「Workers Builds」（GitHub 連携）で、このリポジトリを自動でビルド・公開します。API トークンや GitHub の Secrets は不要です。
1. [Cloudflare](https://dash.cloudflare.com/sign-up) の無料アカウントを作り、メールを認証する
   - **`workers.dev` のサブドメインは、共有サーバーのURL（閲覧リンク）に出ます。** 既定ではメールアドレスの前半が使われることがあります。メールアドレスや本名が分かる名前は避け、好きな名前に変えてください（ダッシュボードの「Workers & Pages」の概要にある「Account details」から変更できます。表記は変わることがあります。変更すると、古いURLは使えなくなるので、閲覧リンクを配る前に済ませてください）
2. ダッシュボードの「Workers & Pages」→「Create application」→「Import a repository」（GitHub を連携）で、このリポジトリを選ぶ
3. Worker 名は `tournament`（`wrangler.jsonc` の `name` と同じにする）。ルートディレクトリは `/`（既定）、ビルドコマンドは空、デプロイコマンドは `npx wrangler deploy`（既定）、本番ブランチは `main`
4. 以後、`main` にマージするたびに自動で公開されます（画面のビルドは `wrangler.jsonc` の `build.command` が行います）。PR のブランチは、プレビュー用にビルドされます。公開先のURLは Worker の画面（`https://tournament.○○.workers.dev`）に表示されます
5. データベース（D1）は `wrangler.jsonc` の `database_id`（本番）と `previews` の `database_id`（PR のプレビュー用。本番データと分けるため別の D1）に設定済みです。別のアカウントで使うときは、D1 を2つ作って書き換えてください。表は初回アクセス時に自動で作られます

### 注意
- 共有されるのは大会データ（参加者名・結果）とコメントです。個人情報になる内容は入れない運用にしてください
- 閲覧にパスワードはありません。**閲覧リンク（共有コード）を知っている人は、誰でも閲覧・コメントできます。** 共有コードは推測しにくい8文字で、存在しないコードを試し続けると一時的に止まります。リンクは参加者にだけ伝えてください。コメントの荒らしは、運営が削除できます
- 運営用パスワードはサーバー側で照合し、ハッシュ化して保存します。間違いが続くと一時的にロックされます。ただし本格的な会員認証ほどの強度ではありません。忘れると運営として入れなくなるので、控えてください。設定する欄（共有を始めるとき・変更するとき）は、入力した文字がそのまま表示されます（ブラウザの自動入力に邪魔されないため）。画面を他の人に見られないようにしてください
- 最後の更新（大会データの送信、またはコメント）から90日たつと、その共有には入れなくなります。データは、次に誰かが共有を作ったときに削除されます（自動の定期削除はありません）。コメントは1つの共有に500件まで、承認待ちの結果の報告は1つの共有に60件まで（1試合3件まで、同じ人は同じ試合を1回だけ）です。結果の報告は運営にだけ見えます
- 任意の対策（共有サーバーへの連打を抑える）: 通常の運用では不要です。必要なら Cloudflare ダッシュボードのレート制限ルールで、`POST /api/rooms` と `PUT /api/rooms/*/state` を IP ごとに制限できます。手順: Cloudflare ダッシュボード → 対象のアカウント → Security（または WAF）→ レート制限ルール → ルールを作成し、URI パスが `/api/rooms` 完全一致（POST）と `/api/rooms/*/state`（PUT）を条件にして、IP ごとに 1分あたり 20 回程度で制限する。コードの側には、同じ秒の連続送信を止める判定（429）だけがあり、それ以上は Cloudflare 側の設定で抑えます
- 無料枠の目安: D1 は1日あたり読み取り500万行・書き込み10万行。閲覧者の自動更新は1回あたり読み取り1〜2行なので、数十人が数時間見る程度なら足ります
- 手元で試すとき: `npm run serve:share`（http://localhost:4174/ 。共有サーバーと同じコードをメモリ上のDBで動かす）

## Windows 版（.exe）

### GitHub Actions で作る（推奨）
- `main` への push・PR・手動実行（Actions → Windows build → Run workflow）で `windows-latest` 上でビルドし、
  起動確認（結果入力・PNG変換・自動保存）を行ったうえで、成果物 `bukatsu-taikai-windows` に `.exe` を添付します
- `v1.0.0` のようなタグを push すると、Releases に `.exe` を添付します

### 手元で作る
Node.js 22 以上が必要です。

```sh
npm ci
npm run dist:win     # dist/bukatsu-taikai-<version>-portable.exe ができる
```

Windows でも Linux / macOS でもビルドできます（Linux では Wine 不要で作成できることを確認済み）。
できた `.exe` はインストール不要の単体ファイルで、ダブルクリックで起動します。
コード署名をしていないため、初回起動時に Windows SmartScreen の警告が出ることがあります（「詳細情報」→「実行」）。

## 開発

```sh
npm ci
npm run build        # src/ → web/app.js、フォント → web/fonts/
npm run icons        # アイコンの画像を作り直す（scripts/icon.svg を直したときだけ。できた web/favicon.svg・web/apple-touch-icon.png・build/icon.ico はコミットする）
npm run serve        # http://localhost:4173/ で確認
npm start            # Electron で起動
npm test             # 単体テスト
npm run test:e2e     # ブラウザ E2E テスト（Playwright）
npm run test:electron  # Electron 版の起動確認
npm run serve:share  # 共有機能を手元で試す（http://localhost:4174/）
```

フォントは IBM Plex Sans JP・IBM Plex Mono（SIL Open Font License 1.1）を同梱しています。`npm run build` が `node_modules` から `web/fonts/` にそろえます（コミットしません）。外部の配信サービスは使わないので、オフラインでも同じ見た目です。ライセンス全文は `web/fonts/LICENSE-*.txt` に入ります。

構成・ルールは `CLAUDE.md`、計画と設計判断は `PLAN.md`、テスト結果は `TEST_REPORT.md`、残課題は `TODO.md` を参照してください。
